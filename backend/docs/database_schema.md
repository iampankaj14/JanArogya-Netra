# JanArogya Netra — Database Schema & Architecture Documentation

This document describes the database schema, security layout, Row Level Security (RLS) scopes, and auxiliary systems for the **JanArogya Netra** backend.

---

## 1. Database Schema Standards

Every table in the JanArogya Netra database adheres to a unified audit and status standard. 

### Standard Columns
All tables include the following 7 standard audit/control fields:
1. `id` `UUID`: Primary Key, defaulted using `gen_random_uuid()` (except `public.users` which maps 1:1 to Supabase `auth.users.id`).
2. `created_at` `TIMESTAMP WITH TIME ZONE`: Defaulted to UTC current timestamp.
3. `updated_at` `TIMESTAMP WITH TIME ZONE`: Defaulted to UTC current timestamp, auto-updated by triggers.
4. `created_by` `UUID`: References `public.users(id)` of the user who created the record. Auto-injected by trigger via `auth.uid()`.
5. `updated_by` `UUID`: References `public.users(id)` of the user who last updated the record. Auto-injected by trigger.
6. `status` `VARCHAR(50)`: Current status constraint (defaults to `'ACTIVE'`, checked against table-specific active sets).
7. `soft_delete` `BOOLEAN`: Flag indicating logical deletion (defaults to `FALSE`).

## 2. Table Specifications

### Administrative and Identity Tables (Core 13)
*   **`roles`**: System roles (`SUPER_ADMIN`, `DHO`, `BMO`, `PHC_STAFF`, `VIEWER`).
*   **`permissions`**: Granular permissions (e.g. `phcs:write`, `reports:read`, etc.).
*   **`role_permissions`**: Maps permissions to roles (RBAC).
*   **`districts`**: District geographic region definitions.
*   **`blocks`**: Sub-district regions linked to a district.
*   **`phcs`**: Primary Health Centers linked to a block. Includes `health_score`, coordinates, and bed allocations.
*   **`sub_centers`**: Local health clinics linked to a PHC.
*   **`villages`**: Grassroots level villages linked to a sub-center.
*   **`users`**: Mirror of Supabase `auth.users` with fields linking users to their role and geographic scopes.
*   **`settings`**: Key-value JSONB system configurations.
*   **`audit_logs`**: Row-level transaction logging (capturing old/new JSON state).
*   **`activity_logs`**: High-level user interaction logs (actions, page hits).
*   **`notifications`**: Regional/user alerts.
*   **`uploaded_documents`**: References to files uploaded in the `documents` bucket.

### Clinical & Operational Tables
*   **`doctors`**: Active physician list assigned to PHCs.
*   **`doctor_attendance`**: Daily log tracking physician attendance.
*   **`patients`**: Patient registry entries.
*   **`patient_visits`**: Patient visits to PHCs detailing symptoms and diagnosis.
*   **`medicine_master`**: Directory of approved medicines, types, and units.
*   **`medicine_stock`**: Current stock levels and alerts thresholds per PHC.
*   **`medicine_stock_history`**: Audit trail of stock inward, outward, and transfers.
*   **`medicine_requests`**: PHC stock shortage replenishment request orders.
*   **`medicine_transfers`**: Inter-PHC supply redistribution shipments.
*   **`resource_requests`**: Requests for staff, beds, or equipment.
*   **`resource_allocations`**: Approved transfers of resources between PHCs.
*   **`disease_cases`**: Outbreak case numbers logged by PHCs.
*   **`disease_predictions`**: Predictive analytical outbreak forecasts.
*   **`dashboard_metrics`**: Pre-aggregated regional statistics for faster dashboard loading.
*   **`chat_history`**: History of conversation sessions with the Gemini AI Netra Assistant.
*   **`ai_recommendations`**: Stock transfer recommendations generated by AI.
*   **`missions`**: Task tracks resolving AI recommendations.
*   **`approvals`**: Workflow multi-step status check approvals.
*   **`rate_limits`**: Log tracking requests per IP per endpoint to enforce limits.

## 4. Row Level Security & Geographical Scoping

Security is enforced using a combination of **RBAC permissions check** and **cascading geographic scope validation**.

### Geographic Scoping Functions
The database includes specialized functions checking access levels from user profiles:
*   `check_district_scope(user_uuid, district_id)`: Limits DHO to their assigned district.
*   `check_block_scope(user_uuid, block_id)`: Limits BMO to their assigned block.
*   `check_phc_scope(user_uuid, phc_id)`: Limits PHC Staff to their assigned PHC clinic.
*   `check_sub_center_scope(user_uuid, sub_center_id)`: Checks access using PHC relationship.
*   `check_village_scope(user_uuid, village_id)`: Checks access cascading through Sub Center relationships.

### Soft Delete Rule
All normal SELECT policies implicitly enforce `(soft_delete = FALSE)`. Only `SUPER_ADMIN` users can select rows where `soft_delete = TRUE` to allow records recovery.

## 5. Storage Bucket Architecture

Five private buckets are configured with file size limit specifications and restricted MIME arrays:

1.  **`documents`**:
    *   **Public**: `false`
    *   **Usage**: Administrative contracts, local audits.
    *   **MIME Restrictions**: PDF, JPEG, PNG.
    *   **RLS Policies**: Restricted to authenticated staff holding `uploaded_documents:read` permission.
2.  **`reports`**:
    *   **Public**: `false`
    *   **Usage**: Compiled epidemiological and clinical summaries.
    *   **MIME Restrictions**: PDF only.
    *   **RLS Policies**: Readable by users with `reports:read`. Writable only by Super Admin and DHO (`reports:write`).
3.  **`profile-images`**:
    *   **Public**: `false`
    *   **Usage**: User avatars.
    *   **MIME Restrictions**: JPEG, PNG.
    *   **RLS Policies**: Readable by authenticated users; users can only upload/delete avatars under folders named after their own UID (`/profile-images/<user_uid>/avatar.png`).
4.  **`medicine-images`**:
    *   **Public**: `false`
    *   **Usage**: Medicine box packaging photos.
    *   **MIME Restrictions**: JPEG, PNG.
    *   **RLS Policies**: Writable only by Admins/DHOs with `medicine:write` permissions.
5.  **`patient-documents`**:
    *   **Public**: `false`
    *   **Usage**: Patient medical documents, consent forms.
    *   **MIME Restrictions**: PDF, JPEG, PNG.
    *   **RLS Policies**: Select/insert granted to users with patient-specific view/edit permissions.

## 6. Advanced Database Functions

### Rate Limiting Checker
Enforced directly in PostgreSQL to prevent denial-of-service/API abuse:
```sql
SELECT public.check_rate_limit(client_ip := '192.168.1.1', rate_endpoint := '/ai/ask-netra', max_requests := 10, window_seconds := 60);
-- Returns TRUE if allowed, FALSE if rate limited. Self-cleans older logs dynamically.
```

### Symmetric Encryption Helpers
Used to encrypt patient details or settings credentials using AES-256 standard via the pgcrypto module:
```sql
-- Encrypt data
SELECT public.encrypt_sensitive_data(plain_text := 'Patient Confidential Phone', secret_key := 'system_db_key');

-- Decrypt data
SELECT public.decrypt_sensitive_data(encrypted_data := '\\x0102...', secret_key := 'system_db_key');
```

## 7. Views & Materialized Views

*   **`v_user_profiles`**: Joins users, roles, and geographical names (district, block, PHC, sub-center, village) for user directories.
*   **`v_active_notifications`**: Filtered unread, active notifications.
*   **`v_medicine_shortages`**: Real-time list of medicines where stock is below the minimum threshold.
*   **`mv_district_epidemiology_summary` (Materialized)**: Pre-aggregated disease cases counts grouped by district, disease, and month.
*   **`mv_phc_health_index` (Materialized)**: Live indicators compiling stock shortages, doctor attendance, and phc status to render regional health index.
*   **`refresh_health_dashboard()`**: RPC function called to concurrency-refresh materialized views without locking tables.
